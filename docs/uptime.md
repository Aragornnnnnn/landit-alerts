# 웹 접속 상태 감시

프로덕션 웹이 응답하지 않으면 `#웹-상태` 채널로 알림이 온다. 복구되면 한 번 더 온다.
이 레포는 여기에 관여하지 않는다. UptimeRobot이 직접 디스코드로 보낸다.

## 왜 바깥 서비스인가

감시자가 우리 안에 있으면 우리와 같이 죽는다.
Sentry는 브라우저에서 코드가 돌아야 에러를 보내므로 화면 자체가 안 뜨는 상황을 잡지 못하고,
GitHub Actions 크론은 최소 주기가 5분인 데다 실제로는 10분 넘게 밀려 다운 감지에 못 쓴다.

무료 플랜을 비교했을 때 디스코드 알림이 들어 있는 곳이 UptimeRobot뿐이라 골랐다.
Better Stack은 무료 알림이 슬랙·이메일이고 디스코드가 유료다.

## 지금 감시하는 것

| 이름    | 주소                    | 간격 |
| ------- | ----------------------- | ---- |
| 랜딧 웹 | `https://www.landit.im` | 5분  |

- 백엔드는 그라파나가 보고 있어 넣지 않았다.
- `/download`는 최종 도착지가 App Store라, 감시하면 우리가 아니라 애플 상태를 재게 된다.

## 세팅 과정

1. **디스코드 웹훅** — `#웹-상태` 채널 편집 > 연동 > 웹후크 > 새 웹후크. 이름 `웹 지켜보는 래디`. URL 복사.
2. **UptimeRobot 알림 연동** — Integrations > Add Discord integration. 웹훅 URL을 넣고 다운·복구 두 이벤트를 켠다. Friendly name도 `웹 지켜보는 래디`로 둔다.
3. **모니터 추가** — Add single monitor. 종류는 HTTP(S), Friendly name `랜딧 웹`, URL은 위 표의 주소. 알림에서 2번 연동을 체크한다. 간격 5분·위치 Default는 기본값 그대로 둔다.
4. **확인** — 대시보드에서 상태가 Up으로 뜨면 끝이다.

대상을 더 넣을 때도 3번만 반복하고, 이 문서의 표에 한 줄 추가한다.

## 주의

- 무료 플랜은 5분 간격이다. 잠깐 죽었다 살아난 건 못 잡을 수 있다.
- 감시 계정은 `landitkorea@gmail.com`이다. 알림 메일도 같이 온다.
