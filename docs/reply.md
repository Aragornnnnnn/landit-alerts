# 리뷰 답글 기능

디스코드 리뷰 알림에서 버튼을 눌러 스토어 리뷰에 개발자 답글을 다는 기능이다.
답글은 App Store·Play Store에 실제로 게시된다.

## 사용법

1. `#⭐-앱-리뷰`의 리뷰 알림에서 **답글 달기**(초록 버튼)를 누른다.
2. 모달에 답글을 쓰고 제출한다.
3. 성공하면 카드에 **답글 — 작성자** 기록이 붙고, 버튼이 **답글 수정**(회색)으로 바뀐다.
4. 수정을 누르면 기존 답글이 채워진 채 열리고, 제출하면 교체된다.
   양쪽 스토어 모두 리뷰당 답글은 1개이며 다시 보내면 덮어써진다.
5. 실패하면 누른 사람에게만 실패 원인(스토어 API 응답)이 표시된다.
   버튼이 "답글 달기"로 남아 있는 리뷰 = 아직 대응 안 된 리뷰다.

모달 상단의 "이 양식이 제출될 거예요..." 경고문은 디스코드가 모든 앱 모달에 강제하는 시스템 문구다. 제거할 수 없다.

## 구조

```text
알림 발송 (GitHub Actions, 30분 cron)
  └─ 리뷰 embed + 답글 버튼 → 디스코드 웹훅 (?with_components=true)

버튼 클릭 이후 (실시간)
  디스코드 → POST https://landit-alerts.vercel.app/api/interactions
    ├─ 서명 검증 (Ed25519, 실패 시 401)
    ├─ 타임스탬프 5분 초과 시 거부 (재전송 공격 방어)
    ├─ 버튼 클릭 → 모달 응답 (수정이면 기존 답글 조회해 프리필)
    └─ 모달 제출 → 스토어 API로 답글 전송
        ├─ 성공 → 카드에 기록 추가 + 버튼 교체
        └─ 실패 → 본인에게만 원인 표시
```

- 발송(cron)과 수신(Vercel)은 별개 인프라다. 알림은 나가는 것뿐이라 cron으로 충분하지만,
  버튼 클릭은 디스코드가 우리를 호출해야 해서 상주 주소가 필요했다.
- 코드는 `api/interactions.mjs`(수신 핸들러)와 `src/interaction-lib.mjs`(순수 로직)에 있다.
- 버튼의 custom_id에 `동작|스토어|리뷰ID`를 인코딩해서 어떤 리뷰의 답글인지 식별한다.
- 리뷰 ID가 `test-`로 시작하면 스토어 전송을 건너뛰고 성공 흐름만 재현한다(시연·테스트용).

## Vercel 세팅 과정 (재현 가능하도록 기록)

수신 서버는 팀 Vercel 계정(aragonn)의 `landit-alerts` 프로젝트다.
전부 CLI로 진행했고, 같은 과정을 반복하면 처음부터 재구성할 수 있다.

1. **토큰 발급** — vercel.com/account/tokens에서 팀 스코프 토큰 생성.
   프로젝트를 새로 만들어야 하므로 특정 프로젝트로 좁힌 토큰은 안 된다.
2. **프로젝트 생성·연결** — 레포 루트에서.

   ```bash
   npx vercel link --yes --project landit-alerts --scope aragonn --token $TOKEN
   ```

   `.vercel/` 폴더가 생기며(커밋 금지, gitignore 처리됨) 이후 명령이 이 프로젝트를 향한다.

3. **환경변수 등록** — 5개, production 환경에. 값은 stdin으로 넣어야 셸 기록에 안 남는다.

   ```bash
   printf '%s' "$값" | npx vercel env add 이름 production --token $TOKEN
   ```

   | 이름                                               | 값                                            |
   | -------------------------------------------------- | --------------------------------------------- |
   | `DISCORD_PUBLIC_KEY`                               | 디스코드 개발자 포털 → 일반 정보 → Public Key |
   | `ASC_ISSUER_ID` / `ASC_KEY_ID` / `ASC_PRIVATE_KEY` | GitHub Secrets와 동일한 ASC 키                |
   | `PLAY_SERVICE_ACCOUNT_JSON`                        | GitHub Secrets와 동일한 서비스 계정 JSON      |

4. **배포**.

   ```bash
   npx vercel deploy --prod --yes --token $TOKEN
   ```

   `api/` 폴더의 함수가 자동 인식된다. 프레임워크·빌드 설정 없음.
   고정 주소는 `https://landit-alerts.vercel.app`.

5. **디스코드 연결** — 개발자 포털 → 일반 정보 → **Interactions Endpoint URL**에
   `https://landit-alerts.vercel.app/api/interactions` 입력 후 저장.
   저장하는 순간 디스코드가 서명된 검증 요청(PING)을 보내고, 응답이 올바르면 저장된다.
   저장 성공 = 서버·서명 검증이 동작한다는 증명이다.

`api/`나 `src/`를 고치면 GitHub 푸시와 별개로 4번(배포)을 다시 실행해야 반영된다.
GitHub Actions(알림 발송)와 Vercel(버튼 수신)은 배포 경로가 서로 다르기 때문이다.

## 보안

- 엔드포인트 주소를 알아도 요청을 위조할 수 없다. 모든 요청은 디스코드의 개인키 서명이 필요하고,
  서버는 등록된 공개키로 검증해 불일치 시 401을 반환한다 (무서명·위조 서명 실측 확인됨).
- 서명된 요청의 재사용(재전송 공격)은 타임스탬프 5분 제한으로 차단한다.
- 실질 권한은 "팀 디스코드 채널에서 버튼을 누를 수 있는가"로 결정된다.
- 스토어 키는 Vercel 환경변수(Sensitive)에만 존재한다.

## 형식 결정 기록

- 버튼: 초록(답글 달기)·회색(답글 수정). 디스코드 버튼 색은 고정 팔레트 5종뿐이라 브랜드 컬러는 불가.
- 이모지: 토스페이스를 이미지로 받아 앱 이모지로 업로드해 사용
  (버튼: 쓰는 손·연필, 답글 기록: 메모). SVG를 브라우저 캔버스로 래스터화해야 투명 배경이 유지된다
  (qlmanage 등은 흰 배경이 생긴다).
- 답글 기록: 빈 줄 간격 → 메모 아이콘 + "답글 — 작성자"(굵은 필드 제목) → 답글 내용.
  작성자는 서버 별명 → 전역 표시 이름 → 계정명 순. 시간은 별도 표기하지 않는다
  (카드의 디스코드 기본 시각과 중복이라 제거).
- 실패는 스레드·카드 기록 없이 본인에게만 표시한다. 버튼 상태가 대응 여부를 이미 보여주기 때문.
