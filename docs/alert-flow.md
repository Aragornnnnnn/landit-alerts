# 알림 판정 흐름과 전환 계획

각 알림이 언제 발송되고 언제 무시되는지, 그리고 데이터 소스를 어떻게 바꿔갈지 정리한다.
공통 전제는 두 가지다.

- 30분마다 스토어에 현재 상태를 물어보고, 지난 실행에 저장한 상태와 비교한다.
- 첫 실행은 기준점만 저장하고 아무것도 보내지 않는다.

## 채널 구성

- `#⭐-앱-리뷰` — 리뷰만 온다.
- `#🚀-앱-소식` — 나머지 전부. 릴리즈, 심사 결과, 이후 추가될 롤아웃·다운로드 요약까지.

## 새 리뷰 → #⭐-앱-리뷰

```text
리뷰 목록 수집
→ 저장된 "본 리뷰 ID 목록"에 없는 ID인가?
  ├─ 예 → 알림 발송, ID를 목록에 추가
  └─ 아니오 → 무시
```

ID 기준이라 같은 리뷰가 두 번 알림될 수 없다.
스토어 응답이 흔들려서 옛 목록이 와도, 이미 본 ID는 전부 목록에 있으므로 조용하다.

## 새 버전 공개 → #🚀-앱-소식

```text
스토어에서 버전 수집
→ 저장된 버전보다 높은가? (숫자 단위 비교)
  ├─ 예 → 알림 발송, 버전 저장
  └─ 아니오 (같거나 낮음) → 무시
```

"다르면 알림"이 아니라 "높아야 알림"이다.
배포 직후 스토어 서버들이 옛 버전을 섞어 응답해도, 낮은 버전은 무시되므로 반복 알림이 없다.

## 애플 심사 상태 → #🚀-앱-소식 (ASC 키 등록 후)

```text
최신 버전의 심사 상태 수집
→ 저장된 상태와 다른가?
  ├─ 출시 대기(PENDING_DEVELOPER_RELEASE)로 바뀜 → 심사 통과 알림
  ├─ 거절(REJECTED·METADATA_REJECTED)로 바뀜 → 심사 거절 알림
  └─ 그 외 전이 → 무시 (상태만 저장)
```

## 하지 않는 것

- **평점 변동 알림** — 평균 평점은 애플·구글 어느 공식 API에도 없다. 공개 캐시 값은 배포 직후 흔들려서 가짜 알림을 만들었고(아래 실사례), 별점만 남긴 평가는 대응할 것도 없어서 알림 가치가 낮았다. 그래서 제거했다.
- **별점만 남긴 평가의 개별 알림** — 누가 몇 점을 남겼는지를 스토어가 아무에게도 제공하지 않는다.
- **Play 심사 완료 알림** — 구글이 API를 제공하지 않는다. 콘솔 이메일이 유일하다.

## 데이터 소스 전환 계획

원칙은 "공식 인증 API가 있으면 그것만 쓴다"이다.
공개 엔드포인트(RSS·lookup·페이지 파싱)는 키 없이 당일 가동하기 위한 임시 소스였고, 키가 등록되는 대로 교체하며 삭제한다.

| 순서 | 조건                  | 하는 일                                                                                                                  |
| ---- | --------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 1    | ASC API 키 등록       | iOS 리뷰·버전을 ASC 공식 API로 교체, 심사 알림 활성화. RSS·lookup 삭제                                                   |
| 2    | Play 서비스 계정 등록 | Android 리뷰 활성화, 버전을 프로덕션 트랙 조회로 교체. 페이지 파싱 삭제                                                  |
| 3    | 1·2 완료 후           | 빌드 처리 완료·실패(애플) → 롤아웃 진행률(양쪽) → 다운로드 주간 요약(양쪽) 순으로 추가                                   |
| 후속 | 1·2 완료 후           | 리뷰 답글 — 알림의 버튼+모달로 작성, 성공 시 ✏️ 수정 버튼으로 교체(기존 내용 프리필). 수신 서버(Cloudflare Workers) 필요 |

## 반복 알림 방어의 배경 — 2026-08-09 실사례

1.1.0 릴리즈 당일, 이런 알림이 실제로 반복됐다.

```text
14:24  평점 4 → 4.3 ▲            (정당)
14:24  랜딧 1.1.0 공개됨          (정당)
19:16  평점 4.3 → 4 ▼ · 리뷰 4개  (가짜 — 리뷰 수까지 과거로 후퇴)
19:16  랜딧 1.0.0 공개됨          (가짜 — 옛 버전을 새 공개로 오인)
22:53  평점 4 → 4.3 ▲            (가짜 — 원상복구를 변동으로 오인)
22:53  랜딧 1.1.0 공개됨          (가짜 — 반복)
```

원인은 스토어 공개 API가 단일 서버가 아니라는 것이다.
전 세계 캐시 서버가 값을 나눠 들고 있고, 값이 바뀐 직후엔 서버마다 최신값과 옛값이 섞여 있다.
호출할 때마다 다른 서버가 응답하므로, 실제로는 한 번 변한 값이 여러 번 변한 것처럼 관측된다.

이 사건으로 두 가지를 바꿨다.
버전 알림에 "높아야 알림" 규칙을 넣었고, 평점 알림은 제거했다.
공식 인증 API로 전환하려는 이유도 같다. 인증 API는 캐시를 거치지 않아 이 문제가 없다.
